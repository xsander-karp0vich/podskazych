# Встроенная база вопросов с собеседований 1С

`questions.jsonl` — главная копия базы знаний Подсказыча. Она лежит в репозитории, уезжает в установщик (`resources/kb`) и есть у каждого пользователя сразу, без сторонних сервисов и без сети.

Модель в базу не ходит сама: приложение ищет по файлу (`src/main/kb/search.ts`) и подкладывает найденное в запрос текстом. Из того же файла строится словарь распознавания речи и определяется тема разговора.

## Формат

Одна строка — один вопрос, JSON с ровно этими полями:

| Поле | Что это |
| --- | --- |
| `UID` | `U0001`…: пишется в журнал созвонов — не менять и не переиспользовать |
| `title` | вопрос |
| `Тема` | ключ темы: `soft`, `perf`, `subd`, `queries`… — список в `src/shared/glossary.ts` |
| `Уровень`, `Приоритет` | `junior`/`middle`/`senior`, `must`/`should`/`rare`; `—` — не задан |
| `Источников` | в скольких источниках встретился вопрос, число |
| `Кратко` | суть для взгляда вскользь — показывается мгновенно, без модели |
| `Ответ вслух` | развёрнутый ответ разговорной речью |
| `Опорные пункты` | пункты через ` • ` |
| `Код` | пример кода, если нужен |
| `Копнут дальше` | что спросят следом, через ` / ` |
| `Если не знаешь` | как ответить, если не помнишь |
| `Поисковые формулировки` | как вопрос звучит у человека, который не знает термина: симптомы, жаргон, ключевые слова |

Пустое `Кратко` — вопрос без ответа: он участвует в поиске темы и словаре, но мгновенной карточки не даёт.

Лишних полей не добавлять: словарь распознавания берёт термины из всех строковых полей, и новое поле молча поменяет его.

## После правок

```
node scripts/kb-check.mjs --write
```

Скрипт проверит поля, UID и темы и перепишет паспорт `manifest.json` (число записей, дата версии, sha256). `npm run dist` без свежего паспорта не соберётся.

Файлы здесь хранятся без преобразования переводов строк (`.gitattributes`): паспорт сверяет содержимое байт в байт.
